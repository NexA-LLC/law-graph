# 事例グラフへの協力

一次資料を1件ずつ、出典と比較上の違いを保って追加します。
収集量に加え、誤読の修正、反対の事例、古い資料の発見も重要な貢献です。

## 協力してほしいこと

| 役割 | 具体的な貢献 |
| --- | --- |
| 法律実務者・研究者 | 主張と判断の区別、判旨の範囲、後続裁判、法改正との関係の確認 |
| 契約・ゲーム等の実務者 | 現場で確認すべき仕様や事実、事例との相違点の提案 |
| 調査・データ担当 | 公開一次資料の発見、事件番号・日付・頁の確認、分類 |
| 開発者 | 取り込み、抽出、検索、検証、更新検知と評価 |

初期に必要なのは多数の無審査な要約ではなく、少数の検証可能な事例です。
専門家以外の投稿も受け付け、何を確認したかを分担して記録します。

## コードを書かずに参加する

GitHubの「公開事例の追加」Issueフォームに、元のURL、資料の種類、
事件・判断日、関係する論点、短い自分の言葉での整理、分からない点を記入してください。

Issueは公開されます。自社・顧客の非公開契約、相談内容、個人情報、
ログインURLや認証情報は投稿しないでください。公表事例でも、分析に不要な住所や
個人識別情報を転載しません。匿名化された人物を推測で特定しません。

## データのPRを出す

1. 一次資料を開いて、判決・行政処分・指針・事業紹介のどれかを確認する。
2. 既存の近い事例ファイルを参考に、別の `*.case-graph.json` を追加する。
3. 元資料の文書ID、取得した内容のハッシュ、取得日時、根拠頁・節を記録する。
4. 当事者の主張、確認された事実、判断、編集者の推論を別のclaimにする。
5. 当時法、未確認の後続経過、現在の案件と異なる条件を記録する。
6. 自分が書いたメタデータ・要約の利用条件を確認し、検証してPRを出す。

```sh
npm ci --ignore-scripts
node src/cli.mjs validate-cases --case-graph data/cases/<topic>/<case-key>.case-graph.json
npm run check
```

同じ出典やテーマのUUIDを共有する場合は、登録済みの記録を維持します。
対象の法令本文が未収録なら、確認済みの条文として登録しません。
公開されていることだけを理由に、第三者の論文・解説・有料データベースの本文を
CC BYで再配布しません。原文の利用条件が未確認ならURLと独自要約に留めます。

プロジェクトへのオリジナルなデータ・要約の寄与はCC BY 4.0、
コード・文書はMITで受け入れます。第三者の原文のライセンスを変更しません。

## レビュー

出典確認と法的解釈の確認を分けます。初期状態は `proposed` です。
「URLを開いた」「ハッシュを記録した」だけでは法的なレビュー済みとしません。

レビューの記録には対象UUID、対象内容のSHA-256、確認範囲、結果、
確認者の公開ハンドル、実際のPRレビューURLと理由を含めます。
記録は追記し、訂正・撤回は以前の記録を `supersedes_id` で指します。
メンテナがGitHub上のレビューと対応する内容を確認して取り込みます。
名前を記入しただけで資格・身元の認証を保証するものではありません。

claimを訂正した場合は新しい内容のUUIDを作り、元資料と既存記録を残します。
元の内容に対する確認は、新しい内容への確認として再利用しません。
